# 绘图执行与证据是否最新

用于整板重画和交付转交，尤其是使用专用写出脚本时。

## 什么能证明执行过

`make_root()` 生成符号、摆放和字段；它不走线。记录实际的走线入口、每页的局部组和走线结果。只调用 `make_root()` 的包装脚本
不能声称执行了 ASG 走线。工程写出脚本扩展了不支持的几何或交叉时，把这种适配限定在本工程，并独立核对它导出的分区和渲染。

不要只改 S 表达式标签就把局部标签转成全局标签。KiCad 的文字方向和外框不同。重新计算朝向、文字间距和连接短线，
再检查 KiCad 渲染。外框盖住继续延伸导线的行内标签需要换锚点/短线。

走线后的清理是设计改动。删除悬空尾线前，先在保留的分支和标签锚点处拆分线段。视觉上多余的一端可能与真实的引脚连接共用一段线。
最后一次清理、图形、标签或字段改动之后重新导出 KiCad XML/ERC；旧的 PASS 结果作废。

## 生成脚本的路径与可复现的转交

生成脚本用显式的 **artifact-root** 放输入，用单独的 **output-root** 放全新的运行结果。工程相对路径的输入按 artifact-root 解析，
不按调用者的工作目录或以前的临时目录。ASG 运行时单独定位；记录实际的技能版本和任何外部依赖。
在交付的脚本旁写明调用方式和必需输入路径及其哈希。保留了脚本不能证明它的路径在打包的交付内能解析。

提供只读的 `--check-inputs` 模式或等效的显式依赖检查。它必须解析并检查必需的输入和绑定的哈希，报告缺失的文件、
未声明的外部依赖和输入/输出路径别名，然后在创建目录、追加日志、写出候选图或调用 `Sheet.build()` **之前**退出。
声明的外部来源/运行时路径要有各自记录的身份；悄悄借用旧的工作树不是依赖约定。不要为发现依赖而执行或导入任意生成代码，
也不要把静态字符串扫描称为完整的路径检查。

打包后，把一份副本放到流程的临时目录下，从另一个工作目录执行那个只读检查。确认声明的输入仍能解析且哈希不变，
并且检查没有改动文件。检查成功只确立输入路径能解析；它不证明生成、KiCad 检查或电气正确。
快照是否最新和生成脚本可复现是两项不同的义务。

构建次数用完时，保留实际失败的脚本、迭代日志和缺失的 KiCad 输出作为证据。路径缺陷仍是明确的转交缺口。
只在另行授权的版本中修正它；输入检查和路径修复都不会补出缺失的原功能原理图，也不允许在已用完的次数上再构建。

## 可读性证据

按 [human-readable-routing.md](human-readable-routing.md)。记录实际追过的路径和未解决的读图障碍，不只是打开了哪些页。
全新的快照可能保存了一张难读的图；它不能确立这项独立的审阅已通过。

转交前，对照每个 OPEN 项的实际义务检查其关闭计划：责任方、目标/状态、所需的输入或动作、获取方式、验收边界和受影响的重跑。
按 [requirements-to-intent.md](requirements-to-intent.md) 中的区分：外部证据、设计保证、工具覆盖和后续环节转交需要不同的动作。
泛泛或不对应的关闭文字报告为交付缺口；新的哈希或一份书面提案都不能关闭它。之后补上实际证据和独立处置时保留原条目。

## 快照检查

最终导出/检查之后，把 `delivery-evidence.json` 存在工程根目录或交付目录的 `record/` 中；放在 `record/` 时其中的路径相对于交付目录
（如 `原理图/board.kicad_sch`）：

```json
{
  "schema_version": 1,
  "root": "board.kicad_sch",
  "inputs": {"board.kicad_sch": "<sha256>", "child.kicad_sch": "<sha256>"},
  "outputs": {"board.xml": "<sha256>", "erc.json": "<sha256>", "geometry.json": "<sha256>", "board.pdf": "<sha256>"},
  "roles": {"netlist": ["board.xml"], "erc": ["erc.json"], "geometry": ["geometry.json"], "render": ["board.pdf"]}
}
```

包含每张活动页、工程配置、符号表和本地 `symbols/*.kicad_sym` 输入。哈希所有引用的输出，用到时包括基线增量和图面审阅记录；
允许 `identity`、`routing`、`visual_review` 等额外角色。存真实的 SHA-256 字符串，不是占位符。

报告交付前立即运行 `python3 scripts/check_delivery_freshness.py <工程>/delivery-evidence.json`。它核对活动层次的覆盖，
拒绝缺失/被改动的输入、输出和必需的角色证据。`FRESH` 只表示这份声明的快照没有变。它不能证明某条命令运行过或有人看过 PDF，
也从不把 ERC 失败、几何缺口、继承的未关闭问题或电气 NO_GO 升为 PASS。

检查器的原始发现与确切的逐对象处置放在一起。KiCad 全局标签外框和保守的本体包络可能需要对照渲染核实；
从不按类别压掉所有标签或所有符号发现。没有另外一套有代表性的回归集，不要把一个工程的走线适配提升进可复用引擎。

几何覆盖比 KiCad 连接窄。显式的页引脚坐标是连接锚点；页框上的任意点不是。KiCad 字段的旋转/镜像改变文字对齐，
不改变存储的绝对字段锚点。校准过的层次标签文字偏移不能使其轮廓或跨页字段合格；保留这些覆盖缺口并做渲染审阅。
单页几何检查项接受任一种文档化的板网络格式，不改变归属，也不忽略跨网接触。

选定工程的标注不完整时，报告每个缺失的符号 UUID、实例路径和可用的工程上下文。位号属性是定位线索，不是回退的身份。
KiCad 导出的对象/引脚数和解析出的源标注数属于不同的范围；得出电气或交付完整性结论前先把它们对上。
