# CopperPilot 参考电路候选

用户要求 CopperPilot 协助时使用。这是一套做法，不是附带的客户端、公开 API 声明或自动的图片转 KiCad 工具。

查官方文档和已安装的受支持入口，看有没有 API、CLI 或 MCP。优先用有文档、并经过任务提交/读回测试的接口。
内部 HTTP/WebSocket 客户端、私有包或认证深链接不能证明有外部设计 API。不得提取凭据或调用私有服务端点来代替。

没有核实到受支持的接口时，用可用的 computer-use 工具操作已安装的界面。记录版本和实际测过的接口。
按器件请求协助时，确认所选的 KiCad 器件和页面。提交确切料号/封装、功能、电压、负载、接口和约束；未定的输入要标出。
查找起点：[官方文档](https://copperpilot.ai/documentation)
和 [参考图做法](https://copperpilot.ai/documentation/product/design/reference-diagrams)。
版本变化时重新核对能力。

配额警告或提交被禁用不算完成查询。获授权时继续查原厂资料，来源分开记录；不得把本地写的设计称为新生成的 CopperPilot 参考。

尽量索取图片/矢量输出、BOM、预期的引脚/网络表、来源和摆放理由。保留原始文件和哈希。导入前检查 CSV 引号、
列数和必需字段：封装字段里的逗号会让列错位。报告格式错误的行，不声称导入成功。

按原厂资料核对确切器件、物理引脚号和封装。区分未知连接、DNP 但有连线的焊盘和有意的 IC NC 引脚；UNKNOWN 不能悄悄变成 NC。
把图片和它的引脚表对照。看起来的线接触、交叉或 SVG 网络名都不是电气事实。由此写出经复核的设计网表和单独的摆放方案。

按设计网表放置真实的 KiCad 符号和可见连接；跨页端口显式保留。按 [electrical-redesign.md](electrical-redesign.md)
核对根图 XML、ERC、几何和 KiCad 渲染。

提交/读回、候选解析、设计网表独立复核和最终 KiCad 检查作为四个独立结果报告。一个环节成功不代表后面的环节通过。
公开的是可复用的做法和中性的测试样例，不是账户数据或私有参考输出。
